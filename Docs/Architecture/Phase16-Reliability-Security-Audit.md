# Phase 16 — Reliability, Threading, Security and Dependency Audit

Status is code-side/static. No Revit host session or project was touched.

## Findings and actions

- **ExternalEvent lifetime (fixed):** `App` held a static `ActionEventHandler`, while shutdown did not release its `ExternalEvent`. The handler now synchronizes its pending callback queue, rejects raises after disposal, discards work rejected by Revit, isolates/logs individual callback exceptions, and disposes the event. Startup failure and `OnShutdown` both clear the static reference and dispose the handler. Autodesk documents `ExternalEvent` as `IDisposable` with `Dispose()` releasing its resources, and `IExternalApplication.OnShutdown` as the add-in shutdown hook: [ExternalEvent](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/05089477-4612-35b2-81a2-89c4f44370ea.htm), [IExternalApplication](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/196c8712-71de-03e8-b30d-a9625bd626d2.htm).
- **Threading:** repository scan found no `Task.Run`, explicit `Thread`, or `Parallel.For/ForEach/Invoke` use in production C#. The two async areas are updater/network flows; neither references Revit DB/UI APIs. The workspace's modeless requests continue through Revit `ExternalEvent` callbacks.
- **Transactions:** 114 source locations instantiate `Transaction`, `TransactionGroup`, or `SubTransaction`. Existing focused transaction acceptance covers Stage 4 ownership/lifecycle and K-Rebar transaction/postcondition contracts; this Phase 16 pass does not claim that every legacy transaction path was behaviorally exercised in a Revit host. The canonical suite remains required.
- **Exception/resource inventory:** 59 empty catches remain in production C#; sampled examples are best-effort UI restoration, optional Revit properties, cleanup, and fallback probes. They are not proof of successful operations. Catch sites around rollback/commit and user-visible generation results must continue to be governed by their checked transaction/postcondition gates. The remaining unclassified catch inventory is residual P2 observability debt, not a known model-corruption path.
- **Document lifetime:** no static `Document`, `UIDocument`, or `Element` fields were found. Modal command forms may hold document-bound objects only for their modal command lifetime; the persistent workspace pane stores no live document/element and resolves commands in Revit's callback context. Host close/switch behavior remains unexecuted and is not labeled host-verified.
- **Secrets / paths / PHM:** no recognized private-key or credential signatures were found in tracked source/config files; no root `.env*` files; no PHM identifiers in production C#. Machine-specific paths appear only as forbidden-pattern strings in acceptance tests.
- **Dependencies:** the project uses four always-on direct NuGet packages (`CommunityToolkit.Mvvm`, `Newtonsoft.Json`, `PdfSharp`, and private `Microsoft.NETFramework.ReferenceAssemblies`), plus conditional Revit API stub packages when local API references are unavailable. Revit API compile references are not shipped at runtime. `dotnet list KhimTools/KhimTools.csproj package --vulnerable --include-transitive` reported no vulnerable packages for current NuGet sources. No upgrade was warranted.
