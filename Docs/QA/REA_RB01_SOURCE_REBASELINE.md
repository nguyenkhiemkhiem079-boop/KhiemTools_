## BL-012 code-side implementation addendum — 2026-10-23

Source SHA: `4bfbda0c7671e52836e27dcf722fb659343ee91c`.

- Added `RebarShapes/rebar-shape-assets.v1.sha256`, version 1, with SHA-256 entries for all 43 packaged `.rfa` families. The entries were recomputed from the 43 source files and match the manifest; manifests copied to both Revit 2024 (`net48`) and Revit 2025 (`net8.0-windows`) build outputs also match the source manifest.
- `RebarShapeAssetIdentity` validates the requested catalog name, strict manifest completeness, exact asset SHA-256, and manifest SHA-256. It persists manifest version, asset name/hash, manifest hash, and the target RebarShape `UniqueId` as Extensible Storage on the loaded element. `GetOrLoadShape` rechecks the asset after Revit loads it, stamps within a `SubTransaction`, verifies after commit, and returns only the same verified element.
- Existing exact-name shapes without the identity record, ambiguous duplicates, and resource/hash mismatches are rejected. The loader shows these conditions and disables loading them as if they were absent. No automatic overwrite or provenance stamp is applied to an old shape.
- Bundle and WiX MSI sources now include the manifest for modern and legacy Revit payloads. The WiX XML files are well formed; an MSI was not built or installed.
- Compile-only builds succeeded for Revit 2025 (`net8.0-windows`, 10 warnings, 0 errors) and Revit 2024 (`net48`, 12 warnings, 0 errors). No tests, Revit command, runtime model, or host was executed.
- Follow-up compile-only compatibility runs at source revision `3e188918a4e6a01ae3d071eca947e223dd80ac0d` also succeeded for Revit 2022, 2023, and 2026. The complete 2022–2026 matrix, warning counts, exact commands, and manifest output hash are recorded in `Docs/QA/REA_RB01_COMPILE_MATRIX.md`.
